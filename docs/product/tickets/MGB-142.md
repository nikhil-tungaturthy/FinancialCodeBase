# MGB-142 — Add resolution guidance to payment exceptions

**Type:** Story
**Priority:** High
**Owner:** Payments Experience

## Problem

Analysts currently read the reason code, then look up the policy themselves, to decide the next step on a held payment. That handoff is slow when a settlement window is about to close.

## Request

On the exception workbench detail, add a **Resolution Guidance** section that:

1. Explains the selected exception in plain language.
2. States the recommended next step.
3. Lists the supporting information that is required.
4. Shows whether a further review or approval is required.
5. Makes an exception that is close to its settlement cutoff visually distinct.
6. Degrades cleanly when the reason code is not in the policy document.

Take the copy from the exception reason policy (`GET /api/v1/policies/exception-reasons` and `app/domain/policies/exception_reasons.json`). Do not hard-code a second set of explanations in the React component.

## Acceptance

- Changing the selected exception changes the guidance.
- MGB-PAY-1042 / MGB-EXC-0231 shows guidance appropriate to a beneficiary name mismatch.
- Assign, note, and existing detail behaviour still work.
- The section is usable on a narrow viewport and exposes a sensible accessible name.
- A frontend test covers the component.
- Backend policy tests stay green.

The baseline does not contain this section.
