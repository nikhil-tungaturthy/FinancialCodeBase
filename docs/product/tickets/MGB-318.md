# MGB-318 — Settlement discrepancy investigation

**Type:** Feature
**Priority:** High
**Owner:** Payments Platform

## Problem

Reconciliation already shows that a batch does not match and which refs were left unmatched. It does not say whether each break is a missing row, a duplicate, or an amount mismatch, and the desk has nowhere to read that classification next to the payment and the ledger.

## Request

Extend settlement reconciliation so that it:

1. Identifies unmatched settlement and ledger records.
2. Distinguishes missing, duplicated, and amount-mismatched entries.
3. Produces a structured discrepancy summary.
4. Links each break to the related payment and ledger entries.
5. Shows that investigation on the batch detail page.
6. Stays idempotent when the same settlement input is reconciled again.
7. Writes an audit event for the run.
8. Has unit and integration tests.
9. Documents what the job does and what it does not do.

The baseline comparison (`app/domain/reconciliation/compare.py`) matches an entry only when it has exactly one principal credit of the same amount. `SB-20260317-SEPA-02` is the worked example: expected 235,367.00 EUR, recorded 253,817.00 EUR, unmatched refs `LE-002448` and `LE-002452`.

Do not call a payment network. The work stays inside this repository.

The baseline does not classify breaks or render an investigation summary.
